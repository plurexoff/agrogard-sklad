# ИТ-Склад AgroGard (Local Edition)

Локальное однопользовательское веб-приложение для учёта ИТ-оборудования на складе
АО «АгроГард». Работает полностью офлайн: без сервера, сети, аутентификации и
многопользовательского режима. Все данные хранятся в браузере (IndexedDB) на этом ПК.

## Запуск

### Вариант 1 — браузерная версия

1. Откройте папку `agrogard-sklad`.
2. Дважды щёлкните по файлу **`index.html`** — приложение откроется в браузере
   (рекомендуются Google Chrome или Microsoft Edge последних версий; поддерживается и Firefox).
3. При первом запуске автоматически загружаются демонстрационные данные
   (5 товаров, 3 сотрудника, несколько операций). Удалить их можно в
   разделе **Настройки → Сбросить все данные**.

### Вариант 2 — исполняемый файл Windows (dist\AgroGardSklad.exe)

1. Скопируйте **`dist\AgroGardSklad.exe`** в любое место (например, на рабочий стол)
   и запустите двойным кликом — откроется отдельное окно приложения без браузерной рамки.
2. Установка не требуется. Требования: Windows 10/11 с **WebView2 Runtime**
   (предустановлен в Windows 11 и в Windows 10 с актуальным Edge).
3. При первом запуске Windows SmartScreen может показать предупреждение
   (файл не имеет цифровой подписи) — нажмите «Подробнее» → «Выполнить в любом случае».

Особенности exe-версии:

- exe самораспаковывается: файлы приложения извлекаются в
  `%LocalAppData%\AgroGardSklad\app\`, там же хранятся данные (IndexedDB в
  профиле WebView2). Удаление exe НЕ удаляет данные; для полного удаления
  дополнительно удалите папку `%LocalAppData%\AgroGardSklad`.
- **Данные exe-версии и браузерной версии хранятся раздельно.** Перенос:
  в исходной версии «Настройки → Экспортировать всё», в новой — импорт CSV
  в разделах «Номенклатура» и «Сотрудники».
- Пересборка exe из исходников: `powershell -ExecutionPolicy Bypass -File build\build-exe.ps1`
  (нужен интернет при первом запуске — скачивается WebView2 SDK для компиляции).

> Установка, Node.js, npm и доступ в интернет не требуются. Внешние библиотеки
> и CDN не используются; диаграммы рисуются средствами CSS.

## Разделы приложения

| Раздел | Назначение |
|---|---|
| **Дашборд** | Сводка на живых данных: 5 KPI-карточек (позиции, единицы, выдано, ниже минимума — с пульсирующим индикатором, гарантии ≤ 30 дней), анимированная donut-диаграмма структуры запасов с центральным числом, горизонтальные бары по категориям на фоне сетки и таблица последних 5 операций с пилюлями статусов и hover-микровзаимодействием строк. |
| **Номенклатура** | Справочник товаров: добавление, редактирование, удаление, поиск (наименование/артикул/производитель), фильтр по категории и метке, подсветка остатка ≤ минимального, сортировка по столбцам, пагинация 25/50/100, импорт/экспорт CSV. На товар можно ставить метки состояния: **новое**, **б/у**, **сломана** (множественный выбор). |
| **Операции** | Журнал складских операций: Приход, Выдача, Возврат, Списание, Корректировка. Фильтры по датам, типу и товару. Удаление ошибочной операции — с предупреждением и автоматическим пересчётом остатка. |
| **Выданное** | Учёт по серийным номерам: серийный номер → товар → получатель → дата → основание. Возврат на склад одной кнопкой. Фильтры по статусу, товару, сотруднику. |
| **Инвентаризация** | Сессии по категории или всем товарам, ввод фактических остатков, автоподсчёт расхождений, закрытие с созданием корректирующих операций, история и ведомости. |
| **Сотрудники** | Справочник сотрудников (ФИО, должность, подразделение, контакты). Используется при выдаче; новый сотрудник добавляется прямо из формы выдачи. |
| **Отчёты** | Остатки на складе, движение за период, выданное оборудование, позиции ниже минимума, инвентаризационная ведомость. Каждый отчёт выгружается в CSV. |
| **Настройки** | Резервное копирование («Экспортировать всё»), шаблоны CSV, полный сброс данных (двойное подтверждение). |

В шапке приложения: **колокольчик** с бейджем числа позиций ниже минимума
(клик открывает отфильтрованную номенклатуру) и плавающая круглая кнопка
**«+»** — быстрое создание товара, прихода или выдачи из любого раздела.

## Серийный учёт

- У товара с флагом **«серийный учёт»** приход оформляется списком серийных
  номеров (по одному на строку) — количество прихода равно числу номеров.
- Выдача и списание выполняются выбором конкретных номеров из доступных.
- Возврат оформляется на экране **Выданное** кнопкой «Вернуть» или через
  «Операции → Возврат».
- Для товаров без серийного учёта ведётся только количественный учёт.
- Корректировка остатка для серийных товаров недоступна (остаток равен числу
  номеров на складе) — используйте приход/списание.

## Импорт CSV

Разделы: **Номенклатура → Импорт номенклатуры / Импорт остатков**,
**Сотрудники → Импорт CSV**. В каждом окне импорта есть кнопка
**«Скачать шаблон»** (те же файлы лежат в папке `templates/`).

Формат файлов:

- кодировка **UTF-8** (с BOM или без), разделитель **`;`** или **`,`** —
  определяется автоматически по первой строке;
- первая строка — заголовки; принимаются английские ключи и русские синонимы
  (`sku`/`артикул`, `name`/`наименование` и т.д.).

`template_products.csv` — обязательные колонки: `sku, name, category, unit, quantity`.
Необязательные: `manufacturer, model, min_stock, serial_tracking (1/0),
warranty_until (ГГГГ-ММ-ДД), comment, tags` (метки через запятую: `новое, б/у, сломана`).
Запись с существующим `sku` обновляется,
новая — создаётся; при расхождении остатка создаётся корректировка.

`template_initial_stock.csv` — пары `sku;quantity`: создаёт приходные операции
для существующих товаров без серийного учёта.

`template_employees.csv` — `full_name` (обязательно), `position, department, contacts`;
обновление по совпадению ФИО.

Порядок импорта: выбор файла → **предпросмотр первых 10 строк** → построчная
валидация с отчётом («строка N: причина») → кнопка **«Загрузить валидные (N)»** →
уведомление о числе созданных/обновлённых/пропущенных записей.

## Экспорт CSV

Все выгрузки: **UTF-8 с BOM**, разделитель **`;`**, экранирование по RFC 4180,
имя файла `agrogard_sklad_[раздел]_ГГГГ-ММ-ДД.csv`. Экспортируются:
номенклатура, журнал операций (с учётом фильтров), сотрудники, выданное
оборудование, все отчёты. Кнопка **Настройки → Экспортировать всё** скачивает
полную резервную копию (4 файла последовательно).

## Замена логотипа

Логотип-заглушка подключён как `<img src="assets/logo.svg">`. Чтобы заменить,
сохраните свой SVG-файл под тем же именем в папку `assets/` (рекомендуемая
высота 40–48 px) и обновите страницу.

## Резервное копирование

Данные хранятся только в IndexedDB текущего браузера. Очистка данных браузера,
переустановка ОС или сбой диска приведут к потере информации. **Регулярно**
(например, раз в неделю и после инвентаризации) нажимайте
**Настройки → Экспортировать всё** и храните CSV-файлы в надёжном месте.

## Технические сведения

- Чистый HTML/CSS/JS (ES2020+), без фреймворков, сборщиков и внешних запросов.
- Хранилище: IndexedDB, база `agrogard_sklad_db`, хранилища: `products`,
  `operations`, `employees`, `serial_items`, `inventories`, `settings`.
- Проведение каждой складской операции выполняется в одной транзакции
  (товар + журнал + серийные номера), что исключает рассинхронизацию остатков.
- Скрипты подключены классически (не ES-модулями) сознательно: по протоколу
  `file://` Chrome/Edge блокируют `type="module"`, а приложение обязано
  запускаться двойным кликом без сервера. Каждый файл — модуль в общем
  пространстве имён `window.AG`.
- Минимальное разрешение 1280×720; корректная работа проверена при 1366×768.
